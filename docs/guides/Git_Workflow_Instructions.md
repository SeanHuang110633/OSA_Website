# 🚀 OSA 專案：功能開發標準作業程序 (SOP)

**Version** : v1
**Release Date** : 2026-01-20
**Author** : Sean

---

### 第一階段：開工準備 (環境同步)

在開始寫任何程式碼之前，必須確保你的基礎是最新且乾淨的。

| 步驟                  | 說明                                            | 對應 Git 指令                      |
| --------------------- | ----------------------------------------------- | ---------------------------------- |
| **1. 切換至主開發線** | 確保自己不在舊的功能分支。                      | `git checkout develop`             |
| **2. 拉取最新進度**   | 確保本地 `develop` 與遠端同步，避免基底過舊。   | `git pull origin develop`          |
| **3. 建立功能分支**   | 以 `develop` 為基底切出新分支，名稱請具描述性。 | `git checkout -b feature/功能名稱` |

---

### 第二階段：開發與提交 (本地循環)

這個階段都在你自己的分支進行，不會影響到別人。

| 步驟                   | 說明                                              | 對應 Git 指令                    |
| ---------------------- | ------------------------------------------------- | -------------------------------- |
| **4. 程式開發**        | 在 IDE (VS Code) 中進行功能實作。                 | _(撰寫程式碼)_                   |
| **5. 暫存變更**        | 將改動的檔案加入暫存區。                          | `git add .`                      |
| **6. 原子提交**        | 撰寫符合規範的 Commit 訊息 (如 `feat:`, `fix:`)。 | `git commit -m "feat: 描述功能"` |
| **7. (進階) 修正紀錄** | 如果剛提交完發現有小錯字，使用修正模式。          | `git commit --amend --no-edit`   |

---

### 第三階段：推送到遠端與發起 PR (協作環節)

這是最重要的步驟，確保你的程式碼能進入 GitHub 進行審核。

| 步驟             | 說明                                                  | 對應 Git 指令                      |
| ---------------- | ----------------------------------------------------- | ---------------------------------- |
| **8. 推送分支**  | **嚴禁**直接 push develop。請推送到你自己的功能分支。 | `git push origin feature/功能名稱` |
| **9. 建立 PR**   | 到 GitHub 網頁點擊「Compare & pull request」。        | _(網頁操作：Base 為 `develop`)_    |
| **10. 處理衝突** | 如果 PR 顯示有衝突，請在本地執行 rebase。             | `git pull --rebase origin develop` |

---

### 第四階段：完畢與清理 (收尾)

當 PR 被合併 (Merged) 之後，為了保持本地環境整潔，請執行：

| 步驟                 | 說明                                     | 對應 Git 指令                    |
| -------------------- | ---------------------------------------- | -------------------------------- |
| **11. 回到主開發線** | 準備下一個任務。                         | `git checkout develop`           |
| **12. 刪除舊分支**   | 既然已經合併，本地的舊分支就可以刪除了。 | `git branch -d feature/功能名稱` |

---

### 💡 小提示

1. **為什麼要先 `git pull origin develop`？**
   如果你在舊的代碼基礎上開發，最後發 PR 時會出現大量的衝突（Conflicts）。每天早上第一件事就是 pull，可以省下後續處理衝突的一小時。
2. **關於 `git add .` 的壞習慣：**
   雖然 `.` 很方便，但請務必檢查是否誤加了 `.env` 或 `node_modules`。建議在 push 前用 `git status` 確認一下。
3. **PR 描述怎麼寫？**
   除了改了什麼，也可以附上一句「測試過後確認 Vue 前端能正確打到 FastAPI 的 XXX API」之類的，反正能促進理解本次修改的都可以打，不設限。
