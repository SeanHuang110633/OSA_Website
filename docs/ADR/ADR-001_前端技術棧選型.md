## 1. 背景 (Context)

本專案（學務處系統重構）原架構為 PHP 建立的單體網頁系統，缺乏前後端分離與現代化開發流程。現有開發團隊組員具備基礎的 HTML/CSS 以及 Vue/Tailwind CSS 的初步修改經驗，但對於前端工程化（打包、依賴管理、全局狀態管理）缺乏系統性理解。為了確保系統的可維護性、開發效率，並兼顧組員的學習曲線，需要選定一套專業且現代的前端技術棧。

## 2. 決策 (Decision)

我們決定採用以下技術組合進行前端開發：

- **框架 (Framework):** Vue 3 (Composition API)
- **建構工具 (Build Tool):** Vite
- **包管理器 (Package Manager):** pnpm
- **樣式框架 (CSS Framework):** Tailwind CSS
- **狀態管理 (State Management):** Pinia
- **通訊工具 (HTTP Client):** Axios

## 3. 專業理由與考量 (Justification)

### A. 開發效率 (Development Efficiency)

- **Vite 的極速開發體驗：** 相比於傳統 Webpack，Vite 利用瀏覽器原生的 ES Modules，實現了「秒級」的冷啟動與熱更新 (HMR)。這對於需要頻繁修改介面的組員來說，能大幅減少等待時間。
- **Tailwind CSS 的原子化設計：** 透過 Utility-first 概念，組員不需再為命名 CSS Class 而苦惱，且能直接在 HTML 中完成大部分樣式調整。其內建的 JIT (Just-in-Time) 引擎確保了最終打包後的 CSS 體積極小。

### B. 系統維護性 (Maintainability)

- **Pinia 的類型安全與簡潔：** 作為 Vuex 的繼承者，Pinia 捨棄了複雜的 Mutation，語法更接近一般函數。這能讓對狀態管理沒概念的組員快速上手，同時提供更好的 TypeScript 支持與調試體驗。
- **Axios 的統一封裝：** 透過 Axios 的攔截器 (Interceptors)，我們可以統一處理全局錯誤訊息、Token 注入等邏輯，避免在各個組件中重複撰寫通訊代碼。

### C. 團隊協作 (Collaboration)

- **pnpm 的高效依賴管理：** pnpm 使用內容尋址存儲 (Content-addressable storage)，不僅節省磁碟空間，更能確保所有組員安裝的依賴版本嚴格一致，解決「在我的電腦跑得起來，你的不行」的常見問題。
- **Vue 的漸進式特質：** Vue 的模板語法（Template）與組員熟悉的傳統 HTML/PHP 非常接近，降低了從舊系統遷移的心智負擔。

## 4. 框架對比 (Comparison)

為了讓這份決策更具權威性，我們橫向對比了三種不同的開發模式：

| **評估維度**     | **純網頁三件套 (Vanilla JS)**      | **React**                            | **Vue 3 (本決策)**               |
| ---------------- | ---------------------------------- | ------------------------------------ | -------------------------------- |
| **開發門檻**     | 最低，只需基礎知識。               | 較高，需理解 JSX 與 Hook 規則。      | **適中，模板語法直觀。**         |
| **開發效率**     | 極低，需手動操作 DOM，易出錯。     | 高，但生態系零散，選型成本高。       | **極高，SFC 與 Vite 整合性強。** |
| **維護性**       | 差，專案變大後會變成義大利麵代碼。 | 極強，但需高度工程素養與嚴謹規範。   | **強，組件化開發，結構清晰。**   |
| **狀態管理**     | 需手動同步，邏輯極度混亂。         | 靈活但複雜（Redux/Zustand）。        | **Pinia 提供穩定且簡單的方案。** |
| **對團隊適配度** | 難以承載學務處系統的複雜需求。     | 對於沒概念的組員來說，學習曲線太陡。 | **最優解，能讓組員在做中學。**   |

## 5. 後果與影響 (Consequences)

### 正面影響 (Pros)

- **專業度提升：** 專案架構符合業界主流標準，有利於組員未來職涯發展。
- **性能優化：** 透過 Vite 與 pnpm，系統的載入速度與構建速度將獲得質的飛躍。
- **程式碼品質：** 透過 Pinia 與 Axios 的規範，能減少冗餘代碼。

### 負面影響 / 挑戰 (Cons)

- **前期配置成本：** 需要負責人（Lead）預先配置好基礎模版與腳手架，並對組員進行短暫培訓。
- **新觀念建立：** 組員需要時間理解「數據驅動 (Data-driven)」而非「DOM 驅動」的思維轉變。
